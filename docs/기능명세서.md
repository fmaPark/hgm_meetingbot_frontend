### AUTH-01: Discord 로그인

**상세 로직:**

1. 버튼 클릭 시 백엔드 /api/login/discord 호출
2. Discord 인증 페이지로 리다이렉트 및 승인
3. Callback URL에서 인증 코드 수신 및 사용자 정보/Role 파싱
4. [자동 가입] DB 확인 후 INSERT/UPDATE
5. [권한 적용] SET-05 규칙에 따라 Role 부여
6. Token 저장 후 대시보드 이동

**예외 처리 및 비고:**

1. 로그인 취소: 사용자가 Discord 인증을 거부한 경우 로그인 페이지로 복귀
2. 미매핑 유저: 매핑된 Role이 하나도 없는 경우 Guest 권한 부여 (대시보드 접근 차단 안내)
3. API 오류: Discord 서버 응답 없음 시 "일시적인 오류" 토스트 노출

**API:** GET /api/login/discord
**우선순위:** P0
**비고:** [설정] Discord Developer Portal에서 Redirect URI 사전 등록 필수 • [Scope] 사용자 Role을 가져오기 위해 guilds.members.read 권한 필요.

### AUTH-02: 토큰 자동 갱신

**상세 로직:**

1. API 요청 시 401 응답 수신
2. 요청 중단 및 POST /token/refresh 호출
3. 갱신 성공 시 Token 업데이트
4. [권한 재확인] Role 변동 반영
5. 중단했던 요청 재시도

**예외 처리 및 비고:**

1. 갱신 실패: Refresh Token 만료 시 즉시 로그아웃
2. 네트워크 오류: 3회 재시도 후 로그아웃

**API:** POST /token/refresh
**우선순위:** P0
**비고:** [구현] Frontend에서 Axios Interceptor 등을 활용하여 전역 처리 권장. • [정책] Access Token 수명: 1시간, Refresh Token 수명: 2주(권장).

### AUTH-03: 로그아웃

**상세 로직:**

1. 버튼 클릭 시 localStorage 데이터 삭제
2. 로그인 페이지로 리다이렉트
3. (Optional) 백엔드 로그아웃 호출

**예외 처리 및 비고:**

1. 이미 로그아웃됨: 로그인 페이지로 리다이렉트

**API:** -
**우선순위:** P0
**비고:** [보안] 보안 수준을 높이려면 Refresh Token을 HttpOnly Cookie로 관리하는 방안 고려 가능.

### AUTH-04: 자동 접근 제어 (RBAC)

**상세 로직:**

1. 로그인 후 Store에 user_role 저장
2. [메뉴 필터링] Role에 따라 메뉴 노출/숨김
3. [페이지 가드] 권한 없는 URL 차단

**예외 처리 및 비고:**

1. 권한 없음: URL 직접 접근 시 403 페이지("접근 권한이 없습니다") 노출
2. 권한 변경: 사용 중 권한이 박탈된 경우, 다음 API 호출 시 403 에러 발생 -> 홈으로 이동

**API:** -
**우선순위:** P0
**비고:** [UX] 새로고침 시에도 권한 정보가 날아가지 않도록 Redux Persist 또는 Zustand Persist 미들웨어 사용 필요.

### DASH-01: 회의 목록 조회

**상세 로직:**

1. 페이지 진입 시 기본 모드(정상) 데이터 로드
2. [정보 표시] 날짜, 프로젝트/파트, 제목, 상태 배지
3. [휴지통 모드 시] 삭제된 날짜(deleted_at)와 남은 보관 기간을 추가로 표시하거나 툴팁 제공

**예외 처리 및 비고:**

1. 데이터 없음: "회의 기록이 없습니다" (모드별 문구 분기 처리)

**API:** GET /meetings
**우선순위:** P0
**비고:** [UI] 휴지통 모드 활성화 시, 리스트 테두리 색상을 붉은색으로 변경하거나 상단에 경고 배너를 띄워 모드 구분을 명확히 함.

### DASH-02: 상태 배지 표시

**상세 로직:**

1. 일반 모드: Recording, Processing, Summarized 등 기존 배지 표시
2. 휴지통 모드: 모든 항목에 🗑 Deleted (또는 삭제됨) 배지 일괄 적용

**API:** GET /meetings
**우선순위:** P0
**비고:** [접근성] 색맹 사용자 고려하여 텍스트 병기.

### DASH-03: 검색 및 필터링

**상세 로직:**

1. [프로젝트] 선택 시 파트 Dropdown 목록 갱신 (Dependent)
2. [검색] 검색어 입력 후 엔터/버튼 클릭 시 조회
3. 조건 변경 시 결과 리스트 갱신 및 1페이지로 초기화
4. 현재 뷰 모드(DASH-04 상태) 내에서 필터링 동작

**예외 처리 및 비고:**

1. 결과 없음: "조건에 맞는 회의가 없습니다" 안내

**우선순위:** P0
**비고:** [성능] 검색어 입력에는 Debounce(300ms) 적용. • [UX] 검색어 입력 중에는 'X' 버튼을 노출하여 빠른 초기화 지원.

### DASH-04: 휴지통 모드 전환

**상세 로직:**

1. [권한 체크] 관리자(Admin) 권한 보유자에게만 토글 버튼 노출
2. [ON 전환] trashed=true 파라미터로 API 호출 (삭제된 목록 조회)
3. [OFF 전환] trashed=false 파라미터로 API 호출 (정상 목록 복귀)
4. 모드 전환 시 기존 필터(DASH-03) 조건은 유지됨

**예외 처리 및 비고:**

1. 필터 유지: 휴지통 모드에서도 '프로젝트 A'가 선택되어 있다면, '프로젝트 A의 삭제된 회의'만 노출

**API:** GET /meetings/deleted
**우선순위:** P0
**비고:** [위치] 필터 영역과 구분되도록 리스트 상단 우측(테이블 헤더 근처)에 배치 권장.

### DASH-05: 실시간 상태 갱신

**상세 로직:**

1. 일반 모드: Processing 항목 존재 시 5초 간격 Polling
2. 휴지통 모드: Polling 로직 비활성화 (삭제된 항목은 상태가 변하지 않음)

**우선순위:** P0
**비고:** [최적화] 휴지통 모드에서는 불필요한 API 호출 방지.

### DASH-06: 요약하기 진입

**상세 로직:**

1. 일반 모드: Stopped 상태 항목에 버튼 노출
2. 휴지통 모드: 모든 액션 버튼 숨김 (복구 전에는 요약 불가)

**우선순위:** P0

### DASH-07: 삭제 및 복구 관리

**상세 로직:**

1. 정상 모드 (Toggle OFF)
   - [삭제](휴지통) 아이콘 노출
   - 클릭 시 임시 삭제 처리 (PUT /trash)
2. 휴지통 모드 (Toggle ON):
   - [복구](Undo) 아이콘 노출
   - 클릭 시 정상 상태로 복원 (PUT /restore)

**예외 처리 및 비고:**

1. 컨펌 메시지
   - 삭제 시: "휴지통으로 이동하시겠습니까?"
   - 복구 시: "선택한 회의를 복구하시겠습니까?"

**API:** DELETE /meetings/{meeting_id}, POST /meetings/{meeting_id}/restore
**우선순위:** P1
**비고:** [UX] 복구 완료 시 해당 항목이 리스트에서 즉시 사라지는 애니메이션(Fade out) 적용 권장.

### MEET-01: 요약 설정 모달 진입

**상세 로직:**

1. [진입] Stopped 상태이며 휴지통이 아닌 경우 버튼 클릭
2. [데이터 로딩] GET /prompts, GET /keywords 호출
3. 로딩된 프롬프트 목록을 Dropdown에 바인딩

**예외 처리 및 비고:**

1. 휴지통 상태: 버튼 미노출
2. 로딩 실패: "설정 정보를 불러오지 못했습니다" 에러 및 재시도 버튼

**API:** GET /prompts, GET /keywords
**우선순위:** P0
**비고:** [UX] 데이터 로딩 중 Dropdown Skeleton 처리.

### MEET-02: 옵션 설정 및 프롬프트 편집

**상세 로직:**

1. [호출] 프롬프트 Dropdown 선택 시, 해당 프리셋의 내용을 하단 Textarea에 자동 입력
2. [수정] Textarea 내 텍스트 자유 편집 가능
3. [저장] 편집된 내용을 [새로 저장] 클릭 시, 이름 입력 팝업 후 POST /prompts 호출하여 프리셋 추가
4. [생성] [생성 시작] 클릭 시 최종 선택된 옵션으로 요약 요청

**예외 처리 및 비고:**

1. 저장 실패: 프롬프트 저장 실패 시 에러 토스트(요약 요청은 계속 진행 가능)
2. Ad-hoc 실행: 저장하지 않고 수정된 텍스트로만 일회성 요약 실행 가능해야 함

**API:** POST /prompts, POST /meetings/{id}/summarize
**우선순위:** P0
**비고:** [데이터 흐름] 요약 요청(summarize) 시, 프롬프트 ID 뿐만 아니라 '수정된 텍스트(prompt_text)' 자체를 보낼 수 있도록 API 설계 필요
